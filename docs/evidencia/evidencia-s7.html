2. Contrato de API Principal (OpenAPI 3.1)

El backend de ROUTB (FastAPI) cuenta con su contrato completamente tipado y exportado en docs/openapi.json. Abarca todos los endpoints clave:

  • Usuarios y Autenticación: POST /users/, GET /users/, POST /auth/login (JWT), GET /auth/me.
  • Viajes y Reservas: GET /trips/, POST /trips/, GET /trips/my-trips, GET /trips/{trip_id}, POST /trips/{trip_id}/cancel, POST /trips/{trip_id}/reservations (consistencia atómica de cupos).
  • Solicitudes y Monitoreo: GET /requests/trips/{trip_id}, POST /requests/{request_id}/accept, POST /requests/{request_id}/reject, GET /health.

3. Estrategia de Integración (ADR-0004)

En el ADR-0004 se seleccionó un patrón de integración asíncrona con Firebase Cloud Messaging (FCM) mediante tareas en segundo plano. Se descartó la comunicación HTTP síncrona bloqueante porque una latencia o indisponibilidad de FCM no debe comprometer la operación principal de reserva de cupos del estudiante ni generar fallos en cascada.

4. Pruebas de Contrato en el Pipeline de CI

Verificación Bidireccional

test_openapi_contract_matches_implementation valida que todas las rutas, métodos HTTP, códigos de respuesta y esquemas coincidan exactamente entre el código en FastAPI y el archivo versionado.

Detección de Breaking Changes

test_contract_detects_incompatible_breaking_change simula la eliminación de una ruta clave y verifica que la prueba falle (AssertionError), garantizando que ningún cambio incompatible pase inadvertido en CI.

# Ejecución de la prueba de contrato en pytest:
pytest backend/tests/test_openapi_contract.py -v

PASSED [100%] backend/tests/test_openapi_contract.py::test_contract_detects_incompatible_breaking_change
